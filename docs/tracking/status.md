# 현재 상태

## 지금까지 된 것

앱 기능은 아직 없다. Next.js 기본 틀과 3D 인체 모델 파일이 있는 상태다.

| 항목 | 상태 |
|---|---|
| Next.js 프로젝트 뼈대 | 있음 (`app/layout.tsx`, `app/page.tsx`는 `create-next-app` 기본 화면 그대로) |
| 3D 인체 모델 | `public/human-body.glb`에 있음. 25개 부위, 111KB, 외부 파일 없음 |
| 모델 편집 원본 | `assets/human-body/`에 있음 |
| `OPENAI_API_KEY` | 로컬 `.env.local`에 넣어 둠. Vercel에는 아직 등록하지 않음 |
| 3D 라이브러리 설치 | 안 됨 |
| 부위 데이터 | 없음 |
| 3D 뷰어 | 없음 |
| 기록 저장 | 없음 |
| 진단 화면 | 없음 |
| AI 연결 | 없음 |
| 홈 화면 | 없음 (기본 화면이 그대로 남아 있다) |
| 통계 화면 | 없음 |

테스트 프레임워크를 도입하지 않기로 했으므로, 자동 검증은 `npm run lint`와 `npm run build`뿐이다.
어떤 기능도 테스트로 검증된 상태가 아니다.

모델 파일 자체는 형식과 부위 정보를 확인했지만, **브라우저에서 실제로 불러와 부위를 눌러 본 적은
없다.** 1번 작업이 그것을 확인하는 일이다.

## 남은 것 (순서대로)

1. **3D 라이브러리 설치와 부위 데이터** — `three`, `@react-three/fiber`, `@react-three/drei`를
   설치하고, `app/lib/bodyParts.ts`에 25개 식별자와 한국어 이름을 넣는다. 식별자는 모델 안의
   덩어리 이름과 정확히 같아야 한다.
2. **3D 뷰어** — `app/components/BodyModel.tsx`. 모델 불러오기, 전신이 잘리지 않게 카메라 맞추기,
   회전·확대, 부위 클릭, 재질 복제, 면 판별, 드래그와 누르기 구분. `app/components/BodyPartPicker.tsx`
   로 이름 목록에서 고르는 방법도 함께 만든다.
3. **기록 저장** — `app/lib/records.ts`에 읽기·쓰기·수정·삭제를 넣는다. 저장 키는
   `bodylog.records`이고, 기록 하나는 `id`·`bodyPartId`·`side`·`symptoms`·`predictedCondition`·
   `summary`·`createdAt`을 갖는다.
4. **진단 화면 (AI 없이)** — `app/diagnose/page.tsx`. 부위 선택 → `app/lib/symptoms.ts`가 계산한
   증상 목록 체크 → 저장까지. 이 단계까지 만들면 AI 없이도 앱이 동작한다.
5. **AI 연결** — `app/api/chat/route.ts`와 `app/lib/chatClient.ts`. `gpt-5-mini`로 대화 주고받기와
   정리 결과 받기. 정리 결과의 부위와 면을 되돌리는 화면까지.
6. **홈 화면** — `app/page.tsx`를 갈아엎는다. 기록이 있는 부위 강조, 부위를 눌러 펼치는 기록 목록,
   각 기록의 수정·삭제.
7. **통계 화면** — 부위별 기록 횟수와 기간별 기록 추이. **그래프를 어떤 도구로 그릴지 아직
   정하지 않았다.** 이 단계에 들어가기 전에 정해야 한다.

1~6이 제출에 필요한 핵심이고, 7은 그 뒤의 일이다.

## 막혀 있는 것

없다. 다만 2번을 시작하기 전에 알아 둘 제약이 하나 있다. 가슴과 등이 한 덩어리, 배와 허리가 한
덩어리라서 몸통 옆면에서는 앞뒤 판별이 흔들린다. 경계 폭을 두어 그 안이면 "옆"으로 판정하는
방식으로 먼저 만들어 본다.

배포 전에 할 일이 하나 있다. **Vercel 프로젝트 설정에 `OPENAI_API_KEY`를 등록해야 한다.** 로컬
`.env.local`은 배포에 따라가지 않는다.
