# 0010 — 질문을 두 번으로 줄이고, 예측을 먼저 보여준 뒤 고친다

## 상황

웹에서 직접 써 보니 AI가 질문을 계속 이어갔다. 질문 수에 한도가 없었고, 결과는 사용자가
"정리하기"를 눌러야만 나왔다. 게다가 `gpt-5-mini`를 기본 추론 강도로 불러 질문 하나에 10~15초가
걸렸다. 결과를 보기 전에 지치는 화면이었다.

## 결정

- **질문은 2번까지만 한다.** 한도는 `app/lib/chatClient.ts`의 `MAX_QUESTIONS`이고, 통로가 이
  값을 AI에게 알려 "지금 몇 번째 질문인지"를 안다. 그래서 AI는 병명을 좁히는 데 가장 도움이 되는
  것부터 묻는다.
- **두 번 답하면 화면이 곧바로 정리를 부른다.** AI가 더 물을 것이 없다고 하면 그보다 일찍 부른다.
  "바로 결과 보기"로 사용자가 먼저 부를 수도 있다.
- **결과 아래에서 맞는지 묻는다.** "맞아요"는 저장, "아니에요"는 다른 점을 적게 해 그 말을 대화
  끝에 붙여 다시 정리한다. 이때 "○○은(는) 아닌 것 같아요"를 앞에 붙여 보내서 같은 병명이 다시
  오지 않게 한다.
- **추론 강도를 낮춘다.** 질문은 `minimal`, 정리는 `low`. 질문 하나가 1.5~2초, 정리가 3~4초로
  줄었다.

## 고르지 않은 것

- **질문마다 그때까지의 예측을 함께 보여준다.** 질문을 줄이지 않아도 중간 결과가 보인다. 탈락
  이유: 응답 형식이 커져 질문마다 느려지고, 화면에 병명이 계속 바뀌며 떠 있으면 무엇이 결과인지
  헷갈린다.
- **질문 없이 부위만 보고 곧바로 예측한다.** 가장 빠르다. 탈락 이유: 부위 하나로는 병명이 너무
  넓어 "흉통" 같은 이름만 나온다. 두 번의 질문이 그 폭을 좁힌다.
- **추론 강도를 그대로 두고 질문만 줄인다.** 결과는 조금 더 정확할 수 있다. 탈락 이유: 두 번만
  물어도 30초 가까이 걸린다. 틀린 예측은 "아니에요"로 고칠 수 있으므로 속도를 택했다.

## 앞으로 무엇이 달라지는가

- 한 번의 진단에서 AI 호출은 보통 3번(첫 질문, 두 번째 질문, 정리)이다. "아니에요"를 누를 때마다
  한 번씩 더 나간다.
- 추론을 짧게 시켜 질문이 가끔 덜 날카롭다(예: 이미 답한 쪽을 다시 묻는 질문). 거슬리면 질문만
  `low`로 올려 본다.
- 면을 바꾸면 대화가 처음부터 다시 시작된다. 같은 부위라 체크한 증상은 남는다.
