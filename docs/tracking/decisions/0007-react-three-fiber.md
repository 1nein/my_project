# 0007 — React 안에서 3D를 다루는 도구로 React Three Fiber를 쓴다

## 상황

3D 모델을 화면에 띄우기로 정하면서(0006) 3D 렌더링 라이브러리가 필요해졌다. 웹에서 3D를 그리는
실질적인 표준은 Three.js인데, 이 앱은 React로 만들어져 있다. Three.js는 React와 다른 방식으로
화면을 다루므로 둘을 잇는 방법을 정해야 한다.

## 결정

`three`에 더해 `@react-three/fiber`와 `@react-three/drei`를 함께 쓴다. 3D 장면을 React 컴포넌트로
쓰고, 모델 불러오기와 카메라 조작은 `@react-three/drei`가 주는 도구를 쓴다.

## 고르지 않은 것

- **Three.js만 직접 쓰기.** 의존성이 하나로 끝나고 Three.js 자료를 그대로 쓸 수 있다. 탈락 이유:
  장면을 만들고 지우는 일, 화면 크기 변경 처리, React 상태와 3D 장면을 맞추는 일을 전부 손으로
  써야 한다. 혼자 만드는 프로젝트에서 이 부분이 버그가 가장 많이 나는 자리이고, 부위 클릭 판정도
  직접 구현해야 한다.
- **3D 모델 뷰어 웹 컴포넌트를 쓰기.** 한 줄로 모델을 띄울 수 있다. 탈락 이유: 이 앱의 핵심은
  모델을 보는 것이 아니라 **부위를 눌러 어느 부위인지 알아내는 것**인데, 그 기능을 세밀하게
  다루기 어렵다. 부위별로 색을 다르게 칠하는 것도 마찬가지다.

## 앞으로 무엇이 달라지는가

- **의존성이 셋 늘어난다.** `package.json`이 그만큼 무거워지고, Next.js나 React를 올릴 때 이
  셋의 호환 버전도 함께 맞춰야 한다.
- 3D 장면 안의 컴포넌트는 일반 HTML 요소를 쓸 수 없다. 3D 안과 밖의 경계를 분명히 두어야 한다.
- 3D를 그리는 컴포넌트는 브라우저에서만 돌아가므로 `"use client"`가 필요하다.
- 부위 클릭은 각 덩어리의 클릭 이벤트로 받는다. 직접 계산할 필요가 없어지는 대신, 뒤쪽 덩어리로
  이벤트가 번지는 것을 막는 처리를 해야 한다.
- 문제가 생겼을 때 Three.js 자료와 이 도구의 자료를 함께 찾아봐야 한다. 같은 일을 하는 방법이 두
  가지로 설명되어 혼란스러울 수 있다.
