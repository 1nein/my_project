# 0005 — 기록을 고치면 저장 일시를 갱신한다

## 상황

저장한 기록을 나중에 고칠 수 있게 했다. 부위를 잘못 골랐거나 증상을 빠뜨렸을 때 지웠다 다시
만드는 것은 번거롭기 때문이다. 그런데 고쳐 저장할 때 기록의 시각을 어떻게 할지가 남는다. 이
값은 홈 화면의 정렬 기준이고, 나중에 만들 기간별 통계의 기준이기도 하다.

## 결정

기록을 고쳐 저장하면 저장 일시를 **고친 시각으로 갱신한다.** 원래 저장한 시각은 남기지 않는다.
그래서 고친 기록이 홈 목록의 맨 위로 올라온다.

## 고르지 않은 것

- **원래 저장한 시각을 그대로 둔다.** 기록의 시각이 "증상이 있었던 때"라는 뜻을 유지한다.
  오타를 고쳤다고 날짜가 오늘로 바뀌지 않으므로 기간별 통계가 실제 증상 시점을 반영한다.
  탈락 이유: 방금 손댄 기록이 목록 아래쪽에 그대로 남아 있어, 고친 결과를 바로 확인하기
  어렵다는 점을 받아들이지 않았다.
- **저장 시각과 수정 시각을 따로 둔다.** 두 요구를 모두 만족한다. 탈락 이유: 필드가 하나 늘고,
  화면마다 어느 값을 쓸지 매번 골라야 한다. 혼자 만드는 앱에 비해 복잡하다.

## 앞으로 무엇이 달라지는가

- **기간별 통계는 "증상이 있었던 때"가 아니라 "마지막으로 손댄 때"를 기준으로 센다.** 통계
  화면을 만들 때 이 점을 알고 만들어야 하며, 화면의 설명 문구도 그에 맞아야 한다.
- 홈에서 한 부위의 기록을 최신순으로 펼칠 때, 오래전 증상이라도 최근에 고쳤으면 맨 위에 온다.
- 기록에 시각 필드는 `createdAt` 하나뿐이다. 수정 시각을 따로 읽으려는 코드를 만들지 않는다.
- 나중에 "증상이 있었던 날짜"를 사용자가 직접 고르게 하고 싶어지면 이 결정을 다시 봐야 한다.
  그때는 시각 필드를 나누는 쪽이 맞다.
