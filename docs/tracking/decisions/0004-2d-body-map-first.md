# 0004 — 인체 그림을 2D로 먼저 만든다

## 상황

인체가 잘 보이고 누르기 자연스러워야 한다는 것이 이 앱에서 가장 중요한 요구다. 돌려볼 수 있는
3D 인체 모델이면 가장 인상적이지만, 만드는 양이 크게 달라진다.

## 결정

앞면·뒷면 두 장의 2D 이미지 위에 부위별 클릭 영역을 얹는 방식으로 먼저 완성한다. 3D 교체는
그 뒤에 한다.

이 결정과 짝으로, **인체 그림을 그리는 코드와 부위 선택 로직을 분리한다.** `BodyMap.tsx`는
그리고 클릭을 알리는 일만 하고, 기록이나 증상을 직접 다루지 않는다.

## 고르지 않은 것

- **처음부터 3D 모델.** 가장 인상적이고, 돌려보면서 부위를 고르는 경험이 2D보다 낫다. 탈락
  이유: 자유롭게 쓸 수 있는 근육 3D 모델을 구하는 일이 먼저 해결되어야 하고, 모델 파일이 커서
  처음 열 때 느려진다. 3D 라이브러리를 새로 붙이고 부위마다 이름이 붙은 메시를 다뤄야 해서
  작업량이 두세 배가 된다. 제출물이 확실히 완성되는 쪽을 먼저 확보하는 편이 낫다.
- **여러 각도의 이미지를 미리 준비해 드래그로 넘기기.** 돌아가는 것처럼 보인다. 탈락 이유:
  각도마다 부위 클릭 영역을 따로 만들어야 해서, 각도 수만큼 작업이 늘어난다. 2D 두 장보다
  훨씬 비싸면서 진짜 3D의 이점은 없다.

## 앞으로 무엇이 달라지는가

- **부위 선택이 그림 표현에 묶이면 안 된다.** `BodyMap.tsx`가 `records.ts`나 `symptoms.ts`를
  가져오는 순간 3D 교체가 불가능해진다. 이 경계가 이 결정의 값이다.
- 부위 좌표 데이터는 2D 이미지 기준이다. 3D로 바꿀 때 이 데이터는 버리게 된다. 부위 식별자
  목록(`bodyParts.ts`)은 그대로 쓴다.
- 앞면과 뒷면을 전환하는 상태가 홈 화면과 진단 화면 양쪽에 필요하다.
- 자유롭게 쓸 수 있는 2D 해부 이미지를 먼저 구해야 한다. 아직 구하지 못했다.
