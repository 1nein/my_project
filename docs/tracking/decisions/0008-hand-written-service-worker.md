# 0008 — 오프라인 캐시를 직접 짠다

## 상황

앱을 홈 화면에 설치해 쓰기로 하면서 오프라인 캐시가 필요해졌다. 두 가지를 노린다. 인터넷이
끊겨도 화면과 3D 모델이 뜨는 것, 그리고 모델 파일을 매번 다시 받지 않는 것이다.

웹에서 이 일을 맡는 것이 서비스 워커인데, 직접 짤 수도 있고 자동으로 만들어 주는 라이브러리를
쓸 수도 있다.

## 결정

`public/sw.js`를 직접 짠다. 약 80줄이고 규칙은 셋뿐이다.

- 이름에 내용 해시가 붙는 파일과 모델·아이콘은 캐시를 먼저 본다.
- 화면은 네트워크를 먼저 보고, 실패하면 캐시를 쓴다.
- `/api/` 아래는 아예 건드리지 않는다.

켜는 것은 `app/components/ServiceWorkerRegistrar.tsx`가 하고, **배포된 환경에서만** 켠다.

## 고르지 않은 것

- **캐시를 아예 두지 않기.** 만들 것이 없고 옛 화면이 남을 걱정도 없다. 탈락 이유: 면접에서
  인터넷이 느리거나 끊기면 3D 모델을 못 받아 앱이 빈 화면이 된다. 보여주는 자리에서 가장
  피하고 싶은 상황이다.
- **PWA 라이브러리를 쓰기.** 설정 몇 줄이면 캐시 규칙과 파일 목록을 자동으로 만들어 준다.
  탈락 이유가 둘이다. 첫째, 이 앱이 필요한 규칙은 위의 셋뿐이라 자동 생성이 주는 이득보다
  빌드 설정과 의존성이 늘어나는 비용이 크다. 둘째, 캐시가 이상하게 동작할 때 생성된 코드
  안에서 원인을 찾아야 한다. 직접 짠 80줄은 그냥 읽으면 된다.

## 앞으로 무엇이 달라지는가

- **`public/sw.js`를 고치면 파일 안의 캐시 이름도 함께 올려야 한다.** 이름이 그대로면 사용자
  기기에 옛 캐시가 남아 고친 내용이 반영되지 않는다. 배포하고도 "왜 안 바뀌지" 하게 되는
  가장 흔한 원인이다.
- 화면을 네트워크 우선으로 두었으므로, 온라인 사용자는 항상 최신 화면을 본다. 대신 오프라인일
  때는 마지막으로 본 화면이 뜬다.
- `/api/`를 건드리지 않으므로 AI 대화는 오프라인에서 동작하지 않는다. 사용자가 주고받은 내용이
  기기 캐시에 남지 않는다는 뜻이기도 하다.
- 캐시 규칙이 늘어나 관리가 버거워지면 그때 라이브러리로 옮기면 된다. 지금 구조는 규칙이 한
  파일에 모여 있어 옮기기 어렵지 않다.
