# 0002 — OpenAI 호출을 서버 통로를 거쳐 한다

## 상황

AI와 대화하려면 OpenAI API 키가 필요하다. Next.js에서는 브라우저에서 바로 부를 수도 있고, 서버
쪽 Route Handler를 하나 만들어 거칠 수도 있다. 브라우저에서 바로 부르면 만들 것이 하나 줄어든다.

## 결정

브라우저는 `app/api/chat/route.ts`를 부르고, OpenAI API는 그 안에서만 부른다. 키는 서버 환경변수
`OPENAI_API_KEY`에만 둔다.

## 고르지 않은 것

- **브라우저에서 OpenAI를 직접 호출.** Route Handler를 만들지 않아도 되고 코드가 한 겹 준다.
  탈락 이유: 브라우저 코드에 들어간 키는 배포된 사이트에서 개발자 도구만 열면 꺼낼 수 있다.
  배포 주소는 공개되어 있으므로 꺼낸 사람이 그 키로 OpenAI를 쓰면 요금이 키 주인에게 청구된다.
  게다가 OpenAI 계열 클라이언트는 브라우저에서 키를 쓰는 것을 기본적으로 막아 두고, 뚫으려면
  위험을 감수한다는 옵션을 일부러 켜야 한다. 만드는 수고 한 겹을 아끼려고 감당할 위험이 아니다.
- **가짜 응답으로 먼저 만들기.** 키 없이 화면을 완성할 수 있다. 탈락 이유: 결국 실제 연결을
  해야 하고, 그때 구조를 다시 잡게 된다. 다만 키가 없을 때 앱이 멈추지 않도록, AI 실패 시에도
  증상만으로 저장되는 경로는 남겨 두기로 했다.

## 앞으로 무엇이 달라지는가

- **브라우저에서 실행되는 코드에 키가 들어가면 안 된다.** 환경변수 이름에 `NEXT_PUBLIC_`을
  붙이는 순간 이 결정이 무의미해진다.
- 대화 내용과 체크한 증상이 서버를 한 번 지나 OpenAI로 간다. 서버가 그것을 저장하지는 않는다.
- 배포처가 서버 실행을 지원해야 한다. 정적 파일만 올리는 방식으로는 이 앱이 동작하지 않는다.
- 오류 처리가 한 겹 늘어난다. 키가 없을 때, OpenAI가 실패할 때, 응답을 읽을 수 없을 때를 각각
  다른 상태 코드로 구분해 돌려줘야 한다.
