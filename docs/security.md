# 보안 정책

## 이 프로젝트가 지키는 것

지켜야 할 자격 증명은 **`OPENAI_API_KEY` 하나뿐**이다. 로그인이 없고, 개인정보를 받지 않고,
서버에 저장하는 데이터가 없기 때문이다.

| 대상 | 지키나 | 이유 |
|---|---|---|
| `OPENAI_API_KEY` | 지킨다 | 새어나가면 남이 이 키로 OpenAI를 쓰고 요금이 키 주인에게 청구된다 |
| 사용자 계정 | 없음 | 로그인 기능을 만들지 않는다 |
| 서버에 저장된 데이터 | 없음 | 기록은 브라우저 안에만 있다 |
| 배포 주소 접근 | 제한하지 않는다 | 아래 "제한하지 않기로 한 것" 참조 |

## 키를 두는 곳

- **있어야 하는 곳**: 로컬에서는 `.env.local`, 배포에서는 Vercel 프로젝트의 환경변수 설정.
  이름은 `OPENAI_API_KEY`.
- **읽어도 되는 곳**: `app/api/chat/route.ts` 안에서 `process.env.OPENAI_API_KEY`로 읽는다.
  서버에서만 실행되는 파일이다.
- **있으면 안 되는 곳**: 브라우저에서 실행되는 어떤 파일에도 키가 들어가면 안 된다. 구체적으로:
  - `"use client"`가 붙은 파일에서 키를 읽지 않는다.
  - 환경변수 이름에 `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 이 접두사가 붙으면 값이 브라우저
    번들에 그대로 들어간다.
  - 키를 화면에 보내는 응답 본문이나 오류 메시지에 넣지 않는다.
  - 키를 코드에 직접 써넣거나 커밋하지 않는다.

**키가 브라우저로 새면** 배포 주소를 연 누구나 개발자 도구의 네트워크 탭이나 번들 파일에서 키를
꺼낼 수 있다. 꺼낸 사람이 그 키로 OpenAI를 쓰면 요금이 키 주인에게 청구된다. 이것이 OpenAI를
브라우저에서 직접 부르지 않는 이유다.

**키가 없거나 잘못되었을 때**: `app/api/chat/route.ts`는 `500`을 돌려주고, 화면은 AI 기능이
동작하지 않는다고 알린다. 증상 체크와 기록 저장은 그대로 동작한다. 키 값이나 OpenAI가 돌려준
원문을 오류 메시지에 담지 않는다.

**키를 바꿔야 할 때**: OpenAI 대시보드에서 기존 키를 폐기하고 새 키를 발급한 뒤, `.env.local`과
Vercel 환경변수를 모두 바꾸고 다시 배포한다. 한쪽만 바꾸면 그쪽만 동작한다.

## 제한하지 않기로 한 것

배포 주소는 누구나 열 수 있고 접근 제한을 두지 않는다. 면접관이 바로 열어볼 수 있어야 하기
때문이다.

그 결과 **누가 열어 대화를 해도 요금이 키 주인에게 청구된다.** 주소를 공개적으로 알리지 않는 것이
유일한 완화책이다. 요금이 걱정되면 OpenAI 대시보드에서 사용량 한도를 걸어 둔다.

## 데이터가 어디에 있는가

- **기록**(부위·증상·예측 병명·요약·시각)은 접속한 기기의 브라우저 `localStorage`에만 있다.
  서버로 전송되지 않고, 서버에 저장되지도 않는다. 기기를 바꾸면 보이지 않는다.
- **대화 내용은 외부로 나간다.** 사용자가 AI와 주고받는 말과 체크한 증상은 서버를 거쳐 OpenAI로
  전송된다. 건강 관련 내용이 외부 서비스로 전송된다는 뜻이다. 기록 전체나 다른 부위의 기록은
  전송되지 않는다. 전송되는 것은 현재 대화 중인 부위의 식별자, 그 부위에서 체크한 증상, 그리고
  그 대화의 메시지뿐이다.
- 브라우저의 저장 데이터를 지우면 기록이 사라진다. 되돌릴 방법이 없다.

## 기록해 두는 것

서버에 로그를 남기지 않는다. 남길 저장소가 없고 남겨야 할 계정 활동도 없다. `app/api/chat/route.ts`
에서 오류가 났을 때만 서버 콘솔에 오류 내용을 출력하되, **요청 본문과 키 값은 출력하지 않는다.**
요청 본문에는 사용자의 건강 관련 대화가 들어 있다.
