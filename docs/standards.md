# 규칙

어기면 빌드가 깨지거나, 검사가 실패하거나, 구조가 어긋나는 것들이다. 취향은 여기 적지 않는다.

## 검증 기준

작업이 끝났다고 말하려면 두 명령이 **모두 통과**해야 한다.

```bash
npm run lint
npm run build
```

- 통과 기준은 종료 코드 0이다. 화면에 보이는 출력만 보고 판단하지 않는다.
- **테스트 프레임워크를 도입하지 않는다.** `package.json`에 테스트 도구를 추가하지 않는다.
  테스트가 없으므로 위 두 명령이 유일한 자동 검증이다.
- 위반 판정: 둘 중 하나라도 종료 코드가 0이 아니면 작업이 끝나지 않은 것이다.

## TypeScript

- `tsconfig.json`의 `strict`가 켜져 있다. 끄지 않는다.
- **`any`를 쓰지 않는다.** 타입을 모르겠으면 `unknown`으로 받고 좁혀서 쓴다.
  위반 판정: 코드에 `any`가 있으면 위반이다.
- 타입 단언(`as`)을 쓸 때는 **바로 윗줄에 왜 안전한지 주석**을 남긴다.
  위반 판정: 주석 없는 `as`가 있으면 위반이다.
- 경로 별칭은 `@/`를 쓴다. `tsconfig.json`이 `@/*`를 프로젝트 루트로 매핑해 두었다.
  `../../` 식으로 두 단계 이상 올라가는 상대 경로를 쓰지 않는다.

## 컴포넌트

- **기본은 Server Component다.** `"use client"`는 상태, 이벤트 처리, 브라우저 API가 필요한
  컴포넌트에만 붙인다.
  위반 판정: `"use client"`가 붙었는데 `useState`·`useEffect`·이벤트 핸들러·브라우저 API 중
  아무것도 쓰지 않으면 위반이다.
- `"use client"`는 가능한 한 트리의 **아래쪽**에 붙인다. 화면 파일 전체에 붙여 모든 자식을
  브라우저 컴포넌트로 만들지 않는다.

## 스타일

- 스타일은 **Tailwind CSS 유틸리티 클래스**로 작성한다.
- **새 CSS 파일을 만들지 않는다.** 전역 스타일이 꼭 필요하면 `app/globals.css`에 넣는다.
  위반 판정: `app/globals.css` 말고 다른 `.css` 파일이 생기면 위반이다.
- 인라인 `style` 속성은 값이 실행 중에 계산될 때만 쓴다(예: 마크의 좌표).

## 언어

- **화면에 보이는 문자열은 한국어**다. 버튼 이름, 안내 문구, 오류 메시지 모두 한국어다.
- **코드 안의 이름은 영어**다. 변수·함수·타입·파일·폴더 이름에 한글을 쓰지 않는다.
  위반 판정: 식별자나 파일 이름에 한글이 있으면 위반이다.

## 이름

- 컴포넌트 파일은 `PascalCase.tsx`이고, 파일 이름과 기본 내보내기 컴포넌트 이름이 같다.
  (예: `BodyMap.tsx` → `export default function BodyMap`)
- `app/lib` 아래 파일은 `camelCase.ts`다. (예: `bodyParts.ts`)
- 라우트 폴더 이름은 소문자다. (예: `app/diagnose/`)
- 타입 이름은 `PascalCase`다. (예: `SymptomRecord`, `BodyPart`)
  기록 타입을 `Record`로 짓지 않는다. TypeScript 내장 `Record<K, V>`와 이름이 겹쳐 같은 파일에서
  둘 다 쓰면 깨진다.

## 구조

이 셋은 어기면 나중에 통째로 고쳐야 하는 규칙이다.

- **`localStorage`를 부르는 곳은 `app/lib/records.ts` 한 곳이다.** 화면과 컴포넌트가
  `localStorage`를 직접 읽거나 쓰지 않는다.
  위반 판정: `app/lib/records.ts` 밖에 `localStorage`가 나오면 위반이다.
- **OpenAI를 부르는 곳은 `app/api/` 아래의 Route Handler뿐이다.** 지금은 `app/api/chat/route.ts`
  하나다. 브라우저에서 실행되는 코드가 OpenAI 주소를 직접 부르지 않는다.
  위반 판정: `app/api/` 밖에 OpenAI 주소나 OpenAI SDK 호출이 나오면 위반이다.
- **인체 그림을 그리는 코드는 기록을 읽거나 쓰지 않는다.** `BodyMap.tsx`는 부위를 그리고 클릭을
  바깥으로 알릴 뿐이다. 마크를 그리는 일은 `BodyPartMarks.tsx`가 받은 값으로 한다.
  위반 판정: `BodyMap.tsx`가 `records.ts`나 `symptoms.ts`를 가져오면 위반이다.

의존 방향은 화면 → 컴포넌트 → `app/lib` 한 방향이다. `app/lib` 안의 파일이 컴포넌트나 화면을
가져오지 않는다.

## 환경변수

- 환경변수 이름에 **`NEXT_PUBLIC_` 접두사를 붙이지 않는다.** 이 접두사가 붙은 값은 브라우저
  번들에 그대로 들어간다.
- `.env`로 시작하는 파일을 **커밋하지 않는다.** `.gitignore`가 이미 막고 있으므로 이 무시 규칙을
  지우지 않는다.
  위반 판정: `git status`에 `.env` 파일이 추적 대상으로 나오면 위반이다.

## 의존성

- 라이브러리를 추가하기 전에 **먼저 사람에게 묻는다.** 이미 들어 있는 Next.js, React, Tailwind
  CSS로 되는 일에 새 라이브러리를 넣지 않는다.
- 설치는 `npm`으로 한다. `package-lock.json`을 지우거나 다른 패키지 관리자의 잠금 파일을 만들지
  않는다.

## 도메인 규칙의 코드 쪽 요구

규칙의 내용이 아니라, 그 규칙을 지키기 위해 코드가 갖춰야 할 구조만 여기 적는다.

- 부위 식별자는 `app/lib/bodyParts.ts`의 목록에서만 나온다. 문자열을 코드 여기저기에 직접 써넣지
  않는다.
  위반 판정: `app/lib/bodyParts.ts` 밖에 `"front."` 또는 `"back."`으로 시작하는 문자열 리터럴이
  있으면 위반이다.
- 기록을 새로 만들 때 고유 식별자와 저장 일시를 붙이는 일은 `app/lib/records.ts`가 한다. 화면이
  이 값을 만들어 넘기지 않는다.
