# 도메인 규칙

3D 인체 모델에서 신체 부위를 골라 증상을 기록하고, AI와 대화해 증상과 예측 병명을 정리해 남기는
앱의 행동 규칙이다. 여기 없는 판단이 필요하면 임의로 정하지 말고 사람에게 묻는다.

## 용어

| 용어 | 뜻 |
|---|---|
| 신체 부위 | 3D 모델에서 고를 수 있는 영역. 모델이 갖고 있는 25개 고정 목록 |
| 면 | 한 부위 안에서 앞인지 뒤인지 옆인지. `front` / `back` / `side` / `unspecified` |
| 증상 | 특정 부위에 대해 저장된 기록들이 담고 있는 증상 이름 |
| 기록 | 부위 하나에 대한 면·증상·예측 병명·요약·시각의 묶음 |
| 대화 | 진단 화면에서 고른 부위에 대해 AI와 주고받는 여러 번의 주고받음 |
| 보기 | AI가 질문과 함께 내놓는 답의 후보. 이름과 한 줄 설명을 갖는다 |
| 정리 결과 | 대화 끝에 AI가 내놓는 부위·면·증상·예측 병명·요약의 묶음 |
| 요약 | 정리 결과의 설명. 줄마다 한 가지씩 적은 짧은 줄들이며 화면에서 목록으로 보인다 |

"증상"은 두 군데서 다른 것을 가리킨다. **부위의 증상 목록**은 그 부위에 저장된 기록들에서 모은
이름들이고, **기록의 증상**은 그 기록 하나가 담고 있는 이름들이다. 앞의 것은 뒤의 것들을 합쳐서
만들어지며 따로 저장되지 않는다.

## 신체 부위

**무엇인가.** 3D 인체 모델에서 사용자가 고를 수 있는 영역. 모델 파일이 갖고 있는 25개 고정
목록이며 앱이 늘리거나 줄일 수 없다.

**무엇을 하는가.** 골라지면 그 부위의 진단 화면을 연다. 홈 화면에서는 그 부위에 기록이 있으면
색으로 구분되어 보인다.

**무엇을 할 수 없는가.** 사용자는 부위를 추가하거나 지우거나 이름을 바꿀 수 없다. 앱이 부위를
새로 만들 수도 없다. 목록을 바꾸려면 3D 모델 자체를 다시 만들어야 한다.

**어떻게 끝나는가.** 고정 목록이므로 사라지지 않는다.

### 규칙

- **부위 식별자는 3D 모델 안에 들어 있는 이름과 정확히 같아야 한다.** 모델의 각 덩어리가 자기
  식별자(`region_id`)와 한국어 이름(`label_ko`)을 갖고 있고, 눌린 부위를 알아내는 근거가 그
  값이다. 앱이 따로 이름을 지어 쓰면 눌러도 맞는 부위를 찾지 못한다.
- **좌우는 사용자의 몸 기준이다.** `left_knee`는 사용자의 왼쪽 무릎이며, 정면에서 볼 때 화면
  오른쪽에 보인다. 카메라를 돌렸다고 좌우 식별자를 뒤집으면 안 된다.
- 한 번에 고를 수 있는 부위는 하나다. 여러 부위를 동시에 고를 수 없다.
- 어깨는 위팔에 포함되고, 가슴과 등은 한 부위이며, 배와 허리도 한 부위다. 이 셋은 모델이 그렇게
  만들어져 있어 앱에서 나눌 수 없다. 앞뒤 구분은 아래 "면"으로 한다.

### 부위 목록

| 식별자 | 표시 이름 |
|---|---|
| `head` | 머리 |
| `neck` | 목 |
| `chest` | 가슴 / 등 |
| `abdomen` | 복부 / 허리 |
| `pelvis` | 골반 |
| `left_upper_arm` | 왼쪽 위팔 / 어깨 |
| `left_elbow` | 왼쪽 팔꿈치 |
| `left_forearm` | 왼쪽 아래팔 |
| `left_wrist` | 왼쪽 손목 |
| `left_hand` | 왼쪽 손 |
| `left_thigh` | 왼쪽 허벅지 |
| `left_knee` | 왼쪽 무릎 |
| `left_shin` | 왼쪽 종아리 / 정강이 |
| `left_ankle` | 왼쪽 발목 |
| `left_foot` | 왼쪽 발 |
| `right_upper_arm` | 오른쪽 위팔 / 어깨 |
| `right_elbow` | 오른쪽 팔꿈치 |
| `right_forearm` | 오른쪽 아래팔 |
| `right_wrist` | 오른쪽 손목 |
| `right_hand` | 오른쪽 손 |

| `right_ankle` | 오른쪽 발목 |

이 25개가 전부다. 목록에 없는 식별자가 어디선가 나오면 그 값은 버리고 사용자에게 다시 고르게
한다.

## 면

**무엇인가.** 고른 부위 안에서 앞쪽인지 뒤쪽인지 옆쪽인지를 나타내는 값. 가슴과 등이 한 부위이고
배와 허리가 한 부위라서, 이 값이 없으면 "등이 아프다"와 "가슴이 아프다"를 구분할 수 없다.

**값은 넷뿐이다.**

| 값 | 뜻 |
|---|---|
| `front` | 앞쪽 |
| `back` | 뒤쪽 |
| `side` | 옆쪽. 앞뒤 어느 쪽이라 하기 어려운 경계 |
| `unspecified` | 정하지 않음 |

### 규칙

- **부위를 누른 지점으로 자동 판별한다.** 누른 지점을 모델 자신의 좌표로 바꾼 뒤 앞뒤 축 값을
  본다. 모델은 앞쪽이 양수 방향이다. 양수 쪽이면 `front`, 음수 쪽이면 `back`, 경계 부근이면
  `side`다. 경계로 볼 폭은 조정할 수 있는 값이다.
- **카메라 방향으로 판별하면 안 된다.** 모델을 돌려놓고 누르면 화면 기준과 모델 기준이 달라진다.
  항상 모델 자신의 좌표로 바꿔서 본다.
- **사용자가 고칠 수 있다.** 정리 결과 화면에서 앞·뒤·옆 중 하나로 바꿀 수 있다. 저장되는 것은
  그 화면에 최종 표시된 값이다.
- 부위 목록에서 이름을 골라 들어온 경우처럼 누른 지점이 없으면 `unspecified`로 둔다.
- 팔·다리·손·발처럼 앞뒤를 나눌 이유가 없는 부위에도 값은 저장된다. 그 부위에서는 화면에 면을
  보여주지 않아도 된다.

## 증상

**무엇인가.** 특정 부위에 대해 저장된 기록들이 담고 있는 증상 이름들을 모은 것.

**무엇을 하는가.** 그 부위를 고르면 목록으로 즉시 표시되어 사용자가 체크할 수 있다.

**무엇을 할 수 없는가.** 부위를 고르는 시점에 AI를 호출해 목록을 만들지 않는다. 저장된 기록에
없는 증상은 목록에 나타나지 않는다.

**어떻게 끝나는가.** 그 이름을 담고 있던 기록이 모두 삭제되면 목록에서 사라진다.

### 규칙

- 부위의 증상 목록은 **그 부위에 저장된 기록들의 증상을 합친 것**이다. 별도의 증상 사전을 두거나
  저장하지 않는다.
- 면이 달라도 같은 부위면 증상 목록을 함께 쓴다. 가슴 기록의 증상이 등을 고를 때도 나타난다.
- 이름이 똑같은 증상은 목록에 한 번만 나타난다. 대소문자와 앞뒤 공백을 제거한 뒤 비교해 같으면
  같은 증상으로 본다.
- 기록이 하나도 없는 부위의 증상 목록은 비어 있다. 이때 화면은 체크할 것이 없는 상태로 시작하고,
  사용자는 곧바로 대화로 넘어간다.
- 기록이 저장될 때마다 그 기록의 증상이 해당 부위의 목록에 반영된다. 쓸수록 목록이 늘어난다.

---

## 기록

**무엇인가.** 진단 흐름 한 번의 결과. 부위 하나에 대한 면·증상·예측 병명·요약·시각의 묶음.

**무엇을 하는가.** 홈 화면에서 그 부위를 색으로 표시하고, 부위를 누르면 내용을 볼 수 있다. 그
부위의 증상 목록을 이루는 재료가 된다.

**무엇을 할 수 없는가.** 하나의 기록이 여러 부위를 담을 수 없다. 부위 없이 저장될 수 없다.

**어떻게 끝나는가.** 사용자가 삭제하면 사라진다. 그 기록만 담고 있던 증상은 해당 부위의 증상
목록에서도 함께 빠진다.

### 담는 것

| 항목 | 필수 여부 |
|---|---|
| 고유 식별자 | 반드시 하나. 저장할 때 자동으로 붙는다 |
| 신체 부위 | 반드시 하나. 부위 목록의 식별자여야 한다 |
| 면 | 반드시 하나. 네 값 중 하나 |
| 증상 | 0개 이상 |
| 예측한 병명 | 비어 있을 수 있다. AI 정리를 받았다면 채워져 있다 |
| 요약 | 비어 있을 수 있다. 줄바꿈으로 나눈 여러 줄일 수 있다 |
| 저장 일시 | 반드시 있다. 저장할 때 자동으로 붙는다 |

### 규칙

- **기록에 남는 증상의 출처는 둘 중 하나다.** 대화를 마치고 정리 결과를 받아 저장하면 **AI가
  정리한 증상**이 남는다. 대화를 건너뛰거나 AI 호출이 실패한 뒤 저장하면 **사용자가 체크한
  증상**이 남는다. 두 목록을 합치지 않는다.
- 사용자가 체크한 증상은 대화 중 AI에게 전달되어 정리에 반영된다. 정리 결과를 저장하는 경우
  체크한 목록 자체는 따로 저장되지 않는다.
- **AI 결과 없이도 저장할 수 있다.** 이때 예측한 병명과 요약은 빈 값이 되고, 증상만 남는다.
  증상도 병명도 요약도 모두 비어 있는 기록은 저장할 수 없다.
- **저장한 기록은 고칠 수 있다.** 부위·면·증상을 바꿀 수 있다. AI 정리를 다시 하지 않고 저장하면
  예측한 병명과 요약은 **그대로 유지된다.** 대화를 다시 해 정리 결과를 받으면 그 값으로 덮어쓴다.
- **기록을 고쳐 저장하면 저장 일시가 고친 시각으로 갱신된다.** 원래 시각은 남지 않는다. 그 결과
  고친 기록이 홈 목록의 맨 위로 올라온다.
- 기록은 접속한 기기 안에만 남는다. 다른 기기로 열면 보이지 않으며, 이는 정상 동작이다.

## 대화

**무엇인가.** 진단 화면에서 고른 부위에 대해 AI와 여러 번 주고받는 대화. AI가 질문 하나와
고를 수 있는 보기를 함께 내놓고, 사용자는 보기를 누르거나 직접 적어 답한다.

**무엇을 하는가.** 몇 번만 묻고 곧바로 부위·면·증상·예측한 병명·요약 다섯 가지를 정해진 형식으로
내놓는다. 맞는지 틀린지는 그 결과를 보고 사용자가 말해 고친다.

**무엇을 할 수 없는가.** 주고받은 말 전체는 저장되지 않는다. 저장되는 것은 정리 결과뿐이다.
병명을 확정된 사실로 말하지 않는다.

**어떻게 끝나는가.** 정리 결과가 나오면 질문은 끝난다. 사용자가 맞다고 하거나 저장하면 기록이
되고, 저장하지 않고 화면을 떠나면 대화와 체크 내용은 남지 않는다.

### 규칙

- **부위를 고르면 AI가 먼저 묻는다.** 빈 입력창을 내밀면 무엇부터 적어야 할지 알기 어렵다.
  첫 질문과 보기를 먼저 받아 두면 누르기만 해도 대화가 시작된다. 기록을 고치는 중일 때는 먼저
  묻지 않는다. 원래 정리 결과를 그대로 두고 증상만 손보려는 경우가 있기 때문이다.
- **질문은 2번까지만 한다.** 사용자가 두 번 답하면 더 묻지 않고 곧바로 정리 결과를 보여준다.
  결과 없이 질문만 길어지면 사용자는 결과를 보기 전에 지친다. 그래서 AI는 병명을 좁히는 데 가장
  도움이 되는 것부터 묻는다. 그보다 먼저 결과를 보고 싶으면 "바로 결과 보기"를 누른다.
  한도는 `app/lib/chatClient.ts`의 `MAX_QUESTIONS`다.
- **결과를 보여준 뒤 맞는지 묻는다.** "맞아요"를 누르면 그대로 저장한다. "아니에요"를 누르면
  무엇이 다른지 적게 하고, 그 말과 함께 다시 정리한다. 이때 AI는 아니라고 한 병명을 다시 내놓지
  않는다. 이 과정은 몇 번이든 되풀이할 수 있다.
- **AI가 더 물을 것이 없다고 하면** 한도 전이라도 곧바로 정리 결과를 보여준다.
- **면을 바꾸면 대화를 처음부터 다시 한다.** 가슴과 등처럼 면이 바뀌면 묻는 곳 자체가 달라져
  앞 면에서 받은 질문과 답이 맞지 않는다. 같은 부위이므로 체크한 증상은 남긴다. AI에게는 면을
  "앞쪽", "뒤쪽"처럼 뜻이 통하는 말로 넘기고, 가슴 / 등에서 앞쪽은 가슴, 뒤쪽은 등이라고 알린다.
- **AI는 한 번에 질문 하나와 보기 2~5개를 내놓는다.** 보기는 12자 이내의 이름과 20자 이내의
  한 줄 설명을 갖는다. 설명은 비어 있을 수 있다.
- **보기는 여러 개 고를 수 있다.** 고른 것들은 쉼표로 이어져 하나의 답으로 올라간다. 그래서 AI는
  서로 겹치거나 한쪽이 다른 쪽을 포함하는 보기를 내놓지 않는다.
- **보기는 마지막 질문에만 붙는다.** 지나간 질문의 보기를 다시 누를 수 있으면 대화가 어디까지
  왔는지 알 수 없어진다. 답하고 나면 그 질문은 지난 이야기가 된다.
- **새 질문이 오면 앞 질문에 체크해 둔 것은 남지 않는다.**
- **보기에 없는 답은 "기타"를 눌러 직접 적는다.** "기타"는 화면이 붙이는 것이며, AI가 보기 안에
  "기타"나 "모르겠어요" 같은 것을 넣지 않는다. 고른 보기와 직접 적은 말은 함께 하나의 답이 된다.
- **답하기 어려운 질문은 건너뛸 수 있다.** 건너뛰면 모르겠다는 답이 올라가고 다음 질문으로
  넘어간다. 답하지 않은 것과 모른다는 것은 다르므로, 아무 답도 보내지 않고 넘어가지는 않는다.
- **보기를 닫았다가 다시 열 수 있다.** 닫으면 질문은 남고 직접 적어 답한다. 다시 열면 닫기 전에
    체크해 둔 것이 그대로 있다. 닫는 것은 보기를 없애는 것이 아니라 잠시 치워 두는 것이다.
- **병명은 항상 "예측한 병명"으로 표기한다.** 확정 표현("~입니다", "~로 진단됩니다")을 쓰지
  않는다. 화면은 병명 옆에 "예측"을 붙여 확정된 진단이 아님을 보인다.
- **정리 결과의 병명은 비워 두지 않는다.** 좁힐 수 없더라도 가장 가능성이 높아 보이는 것을 하나
  적는다. "두통", "요통"처럼 증상에 가까운 넓은 이름이어도 된다. 빈칸은 사용자에게 아무것도
  남기지 않지만, 넓은 이름이라도 있으면 다음에 무엇을 찾아볼지 알 수 있다.
  병명 자체에 "(예측)", "의심" 같은 말을 덧붙이지 않는다. 그 표시는 화면이 한다.
- **요약은 줄마다 한 가지씩 적는다.** 2~4줄이며, 한 줄은 20자 안팎으로 끊는다. 화면은 이 줄들을
  목록으로 보여준다. 줄글로 길게 이어 붙이지 않는다.
  글머리표("-", "*")는 AI가 붙이지 않는다. 화면이 붙인다.
- **대화 중 AI가 다른 부위나 다른 면을 제안할 수 있다.** 사용자가 가슴을 앞쪽으로 골랐는데 대화
  내용이 등을 가리키면 AI는 같은 부위의 `back`을 제안한다. 이때 정리 결과의 부위와 면은 AI가
  제안한 값이 된다.
- **정리 결과 화면에서 사용자가 부위와 면을 되돌릴 수 있다.** 저장되는 것은 그 화면에 최종 표시된
  값이며, AI가 제안한 값이 아니다.
- AI가 내놓은 부위는 부위 목록에 있는 식별자여야 하고, 면은 네 값 중 하나여야 한다. 목록에 없는
  값을 내놓으면 사용자가 처음 고른 값을 그대로 쓴다.
- **AI 호출이 실패하면** 화면에 실패를 알리고, 사용자가 체크한 증상은 그대로 유지한다. 그 상태에서
  증상만으로 저장할 수 있다. 체크 내용을 지우면 안 된다.

## 개념이 만나는 지점

- **기록 삭제 → 증상 목록.** 기록을 지우면 그 기록의 증상이 부위의 증상 목록에서 다시 계산된다.
  같은 이름을 다른 기록도 갖고 있으면 목록에 남고, 그 기록만 갖고 있었으면 빠진다.
- **기록 삭제 → 부위 색.** 그 부위의 마지막 기록을 지우면 홈에서 그 부위의 강조색이 사라진다.
- **기록 수정 → 부위 색.** 부위를 바꾸면 원래 부위의 강조가 사라지고 새 부위가 강조된다. 원래
  부위에 다른 기록이 남아 있으면 강조가 유지된다.
- **기록 수정 → 목록 순서.** 저장 일시가 갱신되므로 고친 기록이 그 부위 목록의 맨 위로 간다.
- **면 수정 → 부위 색.** 면만 바꾸면 강조되는 부위는 그대로다. 면은 색에 영향을 주지 않는다.
- **AI 실패 → 기록.** 병명과 요약이 빈 기록이 만들어지고, 증상은 사용자가 체크한 것이 남는다.
- **AI의 부위 제안 → 부위 색.** 최종 표시된 부위가 강조된다. 처음 고른 부위는 강조되지 않는다.

## 화면 동작 규칙

### 홈 화면

- **화면 전체가 3D 인체다.** 제목도 설명도 두지 않는다. 기록이 하나도 없을 때만 어디를 눌러야
  하는지 한 줄로 알린다.
- 3D 인체 모델 전체가 잘리지 않고 보인다. 드래그로 돌리고 확대·축소할 수 있다.
- **기록이 있는 부위는 강조색으로 칠해진다.** 기록이 없는 부위는 기본색이다. 한 부위에 기록이
  여러 개여도 색은 한 가지이며 개수에 따라 진해지지 않는다.
- 강조된 부위를 누르면 그 부위의 기록이 화면 아래에서 **저장 일시 최신순**으로 올라온다. 부위
  이름은 맨 위에 한 번 나오고, 기록마다 날짜와 면이 함께 보인다. 닫으면 모델만 남는다.
- 펼쳐진 기록마다 수정과 삭제를 할 수 있다. 삭제는 확인을 한 번 물은 뒤 지운다.
- 기록이 **없는** 부위를 누르면 그 부위의 진단 화면으로 넘어간다.
- 뒤쪽 부위를 보려면 모델을 돌린다. 앞면·뒷면 전환 버튼은 두지 않는다.
- 기록이 하나도 없으면 강조 없는 인체 모델만 보인다. 이것이 처음 열었을 때의 정상 상태다.
- 기록 목록만 따로 보는 화면은 두지 않는다. 기록은 부위를 눌러서만 본다.
- **드래그와 누르기를 구분한다.** 손가락이나 마우스가 일정 거리 이상 움직였으면 돌리기로 보고
  부위를 고르지 않는다. 이 거리는 조정할 수 있는 값이다.
- 손목·발목처럼 작은 부위는 확대해서 고를 수 있어야 한다. 그와 별개로 **부위를 이름 목록에서
  고르는 방법**도 함께 제공한다. 3D를 조작하기 어려운 사용자를 위한 것이다.

### 진단 화면

순서는 다음과 같다.

1. 부위를 고른다. 홈에서 눌러 들어왔으면 이미 골라져 있다. 고르지 않은 채로 들어오면 3D
   모델이 뜨고, 누른 지점으로 면이 함께 정해진다.
2. 고른 부위와 면은 위쪽 막대에만 나온다. 부위를 바꾸는 것도 그 막대에서 한다. **같은 이름을
   화면 아래에 다시 적지 않는다.**
3. 그 부위의 증상 목록이 즉시 표시된다. 사용자가 체크한다. 목록이 비어 있으면 아무것도 그리지
   않는다.
4. AI가 던지는 질문에 보기를 체크해 답한다. 여러 개를 골라도 되고, 보기에 없으면 "기타"를 눌러
   직접 적는다. 답하기 어려우면 건너뛴다. 질문은 2번까지다.
5. 두 번 답하면(또는 "바로 결과 보기"를 누르면) AI가 부위·면·증상·예측한 병명·요약을 내놓는다.
   AI가 부위나 면을 바꿔 제안했다면 이 화면에서 되돌릴 수 있다.
6. 결과 아래에서 맞는지 답한다. "맞아요"는 저장이고, "아니에요"는 다른 점을 적어 다시 예측받는다.

- 4~5단계를 건너뛰고 **증상만 체크해서 바로 저장**할 수 있다.
- 저장하지 않고 화면을 떠나면 체크 내용과 대화가 남지 않는다.
- 홈에서 수정을 눌러 들어온 경우 화면이 그 기록의 내용으로 채워져 있고, 저장하면 새 기록이 생기지
  않고 그 기록이 바뀐다.
- 3D 모델은 부위를 아직 고르지 않았을 때만 보인다. 고르고 나면 글을 읽고 고르는 화면이 된다.
  모델을 보여줄 때는 고른 부위만 강조색으로 칠해진다.

### 통계 화면

아직 만들지 않았다. 만들 때 담을 것은 부위별 기록 횟수와 기간별 기록 추이 두 가지이며, 기간별
추이는 기록의 저장 일시를 기준으로 센다.
