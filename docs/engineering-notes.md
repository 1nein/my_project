# 알아두면 걸리지 않는 것

## 한 부위를 칠했는데 온몸이 같이 칠해진다

**증상.** 오른쪽 무릎을 골라 색을 바꿨더니 머리부터 발끝까지 25개 부위가 전부 같은 색이 된다.

**원인.** `human-body.glb`는 재질을 **하나만** 갖고 있고 25개 덩어리가 그것을 공유한다. 한
덩어리의 `material.color`를 바꾸면 그 재질을 쓰는 모든 덩어리가 같이 바뀐다.

**대응.** 모델을 불러온 직후, 덩어리를 훑으면서 각자의 재질을 복제해 자기 것으로 바꿔 준다.
복제는 한 번만 하고 결과를 들고 있는다. 매 렌더마다 복제하면 메모리가 계속 늘어난다. 덩어리가
재질을 배열로 갖고 있는 경우도 있으니 배열이면 원소마다 복제한다.

**확인 방법.** 한 부위를 고른 뒤 다른 부위 색이 그대로인지 눈으로 본다. 부위를 바꿔 골랐을 때
이전 부위가 기본색으로 돌아오는지도 함께 본다.

## 모델을 돌리기만 했는데 부위가 선택된다

**증상.** 인체를 드래그해서 돌리고 손을 뗐을 뿐인데 마지막에 손가락이 있던 부위가 선택된다.
모바일에서 특히 자주 일어난다.

**원인.** 클릭·탭 이벤트는 누른 곳과 뗀 곳이 같은 요소이기만 하면 발생한다. 드래그로 회전하는
동작도 조건을 만족한다.

**대응.** 누르기 시작한 지점을 기억해 두고, 뗄 때까지 움직인 거리가 기준을 넘으면 선택으로 보지
않는다. 포인터가 취소되는 경우도 같이 처리한다. 기준 거리는 조정할 수 있는 값이며, 손가락이
마우스보다 많이 흔들리므로 넉넉하게 잡는다.

**확인 방법.** 모바일 화면 크기로 줄여 놓고 인체를 크게 한 바퀴 돌려 본다. 돌린 뒤 아무 부위도
선택되지 않아야 한다.

## 드래그와 누르기를 직접 세면 틀린다

**증상.** 드래그가 선택으로 처리되지 않게 하려고, 감싸는 `div`에서 포인터가 눌린 지점과 움직인
거리를 직접 기록해 판정했다. 그런데 회전 드래그가 여전히 선택으로 처리되거나, 반대로 가만히
누른 것까지 드래그로 처리되어 아무것도 선택되지 않았다.

**원인.** 두 가지가 겹친다. 회전 조작이 포인터를 붙잡아 가면 중간 움직임 이벤트가 바깥
`div`까지 오지 않는다. 그리고 창 기준 좌표(`clientX`/`clientY`)는 누르고 있는 동안 페이지가
스크롤되면 값이 따라 움직여서, 손을 대지 않아도 움직인 것처럼 보인다.

**대응.** 직접 세지 말고 3D 층이 주는 `delta`를 쓴다. 클릭 이벤트의 `event.delta`가 누르기
시작한 지점부터 뗀 지점까지의 픽셀 거리이며, 포인터가 붙잡힌 상황에서도 정확하다. 이 값이
기준보다 크면 선택하지 않는다.

**확인 방법.** 모델을 크게 한 바퀴 돌리고 손을 뗀다. 아무 부위도 선택되지 않아야 한다. 이어서
같은 자리를 그냥 누른다. 이번에는 선택되어야 한다.

## 저장소를 `useEffect`에서 읽으면 검사에 걸린다

**증상.** `useEffect` 안에서 `localStorage`를 읽어 `setState`로 넣었더니 `npm run lint`가
"Avoid calling setState() directly within an effect"로 실패한다.

**원인.** React Compiler 검사 규칙이다. 효과 안에서 곧바로 상태를 바꾸면 렌더가 연쇄적으로
일어난다는 이유로 막는다. 저장소처럼 React 바깥에 있는 값은 효과로 끌어오는 대신 구독해서
읽으라는 뜻이다.

**대응.** `useSyncExternalStore`로 읽는다. 구독 함수와 값을 돌려주는 함수를
`app/lib/records.ts`에 두었다. 이때 값을 돌려주는 함수는 내용이 같으면 **같은 객체**를 돌려줘야
한다. 매번 새 배열을 만들면 렌더가 끝없이 반복된다. 그래서 읽은 결과를 캐시해 두고 저장할 때만
버린다. 서버에는 저장소가 없으므로 서버용 값은 항상 같은 빈 배열 하나를 돌려준다.

**확인 방법.** `npm run lint`가 통과하고, 기록을 저장하거나 지웠을 때 화면이 새로고침 없이 바로
바뀌면 된 것이다.

## 모델을 돌려 놓으면 앞뒤가 뒤바뀐다

**증상.** 등을 누르려고 모델을 180도 돌린 뒤 눌렀는데 `front`로 기록된다. 또는 정면에서 가슴을
눌렀는데 `back`이 나온다.

**원인.** 누른 지점을 화면이나 세계 좌표 그대로 판단했기 때문이다. 카메라를 돌리면 그 좌표계는
같이 돌아간다.

**대응.** 교차 지점을 **모델 루트의 자기 좌표로 변환한 뒤** 앞뒤 축 값을 본다. 이 모델은 +Z가
앞이다. 변환한 값이 양수 쪽이면 `front`, 음수 쪽이면 `back`, 0 부근이면 `side`다. 좌우 식별자도
마찬가지로 카메라 방향에 따라 뒤집으면 안 된다. `left_knee`는 카메라가 어디 있든 사용자의 왼쪽
무릎이다.

**확인 방법.** 정면에서 가슴을 눌러 `front`가 나오는지 보고, 180도 돌려 같은 부위를 눌러 `back`이
나오는지 본다.

## `AGENTS.md`의 표시 구간이 되살아난다

**증상.** `AGENTS.md`에서 `<!-- BEGIN:nextjs-agent-rules -->`부터
`<!-- END:nextjs-agent-rules -->`까지를 지우고 커밋해도, `npm run dev`를 돌리면 다시 생겨 있다.
작업 중이던 브랜치에 계속 추적되지 않은 변경이 뜬다.

**원인.** `node_modules/next/dist/server/lib/generate-agent-files.js`가 개발 서버를 띄울 때 이
구간이 없거나 낡았으면 다시 써 넣는다.

**대응.** 지우려 하지 말고 그대로 둔다. 같은 파일의 `upsertAgentRulesBlock`은 **표시 구간만**
교체하고 그 앞뒤 내용은 건드리지 않으므로, 구간 밖에 쓴 내용은 안전하다. `CLAUDE.md`와
`AGENTS.md`를 같은 내용으로 유지할 때도 이 구간을 양쪽에 그대로 포함시키면 된다. 두 파일 중
하나라도 최신 구간을 갖고 있으면 개발 서버는 아무것도 쓰지 않는다.

**확인 방법.** `npm run dev`를 한 번 띄웠다 끄고 `git status`를 본다. `AGENTS.md`가 변경 목록에
없으면 된 것이다.

## `localStorage`는 서버에서 읽을 수 없다

**증상.** 기록을 읽는 코드를 넣었더니 `localStorage is not defined`로 빌드나 첫 렌더가 깨진다.
또는 화면이 잠깐 빈 상태로 보였다가 내용이 나타나면서 콘솔에 렌더 불일치 경고가 뜬다.

**원인.** Next.js App Router의 컴포넌트는 기본적으로 서버에서 먼저 실행된다. 서버에는 브라우저
저장소가 없다. `"use client"`를 붙여도 첫 렌더는 서버에서 한 번 일어나므로, 렌더 중에 저장소를
읽으면 서버 결과와 브라우저 결과가 달라진다.

**대응.** 저장소를 읽는 일은 `"use client"` 컴포넌트의 `useEffect` 안에서 한다. 렌더 함수 본문에서
읽지 않는다. 첫 렌더에는 빈 상태를 그리고, 읽어온 뒤 상태를 채운다. 기록이 없는 것과 아직 읽지
않은 것을 구분하고 싶으면 상태를 `null`(아직 읽기 전)과 `[]`(읽었는데 없음)로 나눈다.

3D 렌더링도 같은 이유로 브라우저에서만 돌아간다. 모델을 그리는 컴포넌트는 `"use client"`여야
한다.

**확인 방법.** `npm run build`가 통과하고, 개발 서버에서 그 화면을 새로고침했을 때 콘솔에
하이드레이션 경고가 없으면 된 것이다.

## Tailwind CSS 4는 설정 파일이 없다

**증상.** `tailwind.config.js` 또는 `tailwind.config.ts`를 찾는데 없다. 만들어서 설정을 넣어도
반영되지 않는다.

**원인.** 이 프로젝트는 Tailwind CSS 4를 쓴다. 4버전은 CSS 파일에서 설정한다.
`app/globals.css`가 `@import "tailwindcss"`로 Tailwind를 가져오고, 색·폰트 같은 값은 같은 파일의
`@theme inline { ... }` 블록에서 정의한다. PostCSS 연결은 `postcss.config.mjs`가 한다.

**대응.** 새 색이나 폰트를 추가하려면 `app/globals.css`의 `@theme inline` 블록에 CSS 변수를
더한다. 설정 파일을 새로 만들지 않는다.

**확인 방법.** 추가한 값을 유틸리티 클래스로 쓴 화면을 개발 서버에서 열어 실제로 적용되는지 본다.
