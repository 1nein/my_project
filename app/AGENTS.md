# `app/`

이 앱의 모든 실행 코드가 여기 있다.

## 담당하는 것

| 경로 | 담당 |
|---|---|
| `layout.tsx` | 모든 화면을 감싸는 틀, 전역 폰트와 스타일 연결 |
| `page.tsx` | 홈 화면 — 기록이 있는 부위를 강조한 3D 인체, 부위를 눌러 펼치는 기록 목록 |
| `diagnose/page.tsx` | 진단 화면 — 부위 선택, 증상 체크, AI 대화, 저장 |
| `api/chat/route.ts` | OpenAI 호출 통로. 서버에서만 실행된다 |
| `components/` | 화면을 이루는 조각들. 3D 인체를 그리는 컴포넌트도 여기 있다 |
| `lib/` | 데이터와 계산 — 부위 목록, 기록 저장, 증상 계산, 통로 호출 |

## 담당하지 않는 것

- **3D 모델 파일**은 `public/human-body.glb`에 있다. 여기에 모델이나 이미지 파일을 넣지 않는다.
- **모델 편집 원본과 생성 스크립트**는 `assets/human-body/`에 있다. 앱 실행에 쓰이지 않으므로
  여기서 가져오지 않는다.
- **빌드·검사 설정**은 프로젝트 루트의 `next.config.ts`, `eslint.config.mjs`, `tsconfig.json`,
  `postcss.config.mjs`가 갖는다. 여기서 설정을 바꾸지 않는다.
- **환경변수 파일**(`.env.local`)은 프로젝트 루트에 둔다.
- 서버에 데이터를 저장하는 코드는 여기 없다. 이 앱에는 서버 데이터베이스가 없다.

## 항상 지켜야 하는 것

- **`localStorage`를 부르는 곳은 `lib/records.ts` 한 곳이다.** 화면과 컴포넌트가 저장소를 직접
  읽거나 쓰지 않는다. `lib/records.ts` 밖에 `localStorage`라는 이름이 나오면 어긴 것이다.
- **OpenAI를 부르는 곳은 `api/` 아래의 Route Handler뿐이다.** 지금은 `api/chat/route.ts` 하나다.
  브라우저에서 실행되는 코드가 OpenAI 주소를 부르거나 API 키를 읽지 않는다. `api/` 밖에 OpenAI
  호출이 나오면 어긴 것이다.
- **API 키는 `api/chat/route.ts`에서 `process.env.OPENAI_API_KEY`로만 읽는다.** 환경변수 이름에
  `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 붙이면 키가 브라우저 번들에 그대로 들어간다.
- **모델 이름도 `api/chat/route.ts` 한 곳에만 둔다.** 지금은 `gpt-5-mini`다. 다른 파일에 모델
  이름을 써넣지 않는다.
- **`components/BodyModel.tsx`는 기록을 다루지 않는다.** 모델을 그리고, 눌린 부위의 식별자와 면을
  바깥으로 알릴 뿐이다. 어느 부위를 강조할지는 바깥에서 받은 목록으로 정한다.
  `lib/records.ts`나 `lib/symptoms.ts`를 가져오면 어긴 것이다.
- **모델을 불러온 직후 덩어리마다 재질을 복제한다.** 25개 덩어리가 재질 하나를 공유하고 있어서,
  복제하지 않고 색을 바꾸면 온몸이 함께 바뀐다.
- **부위 식별자 문자열은 `lib/bodyParts.ts`에서만 나온다.** 다른 파일에 `"right_knee"` 같은
  문자열을 직접 써넣지 않는다. 이 파일의 25개 식별자는 모델 안의 덩어리 이름과 정확히 같아야
  한다.
- **좌우는 사용자 몸 기준이다.** 카메라를 돌렸다고 `left_`와 `right_`를 뒤집지 않는다.
- **의존 방향은 화면 → `components/` → `lib/` 한 방향이다.** `lib/` 안의 파일이 컴포넌트나 화면을
  가져오지 않는다.
- **기본은 Server Component다.** `"use client"`는 상태·이벤트·브라우저 API가 필요한 컴포넌트에만
  붙이고, 트리의 되도록 아래쪽에 붙인다. 3D를 그리는 컴포넌트는 브라우저에서만 돌아가므로
  `"use client"`가 필요하다.

## 이 폴더의 작성 방식

- 화면에 보이는 문자열은 한국어, 코드 안의 이름은 영어다.
- 컴포넌트 파일은 `PascalCase.tsx`이고 파일 이름과 기본 내보내기 이름이 같다. `lib/` 아래
  파일은 `camelCase.ts`다.
- 스타일은 Tailwind CSS 유틸리티 클래스로 쓴다. 새 `.css` 파일을 만들지 않는다. 전역 스타일이
  필요하면 `globals.css`에 넣는다.
- 3D 장면 안에서는 일반 HTML 요소를 쓸 수 없다. 3D 안과 밖의 경계를 컴포넌트로 분명히 나눈다.
- `any`를 쓰지 않는다. 타입 단언을 쓸 때는 바로 윗줄에 왜 안전한지 주석을 남긴다.
- 다른 폴더로 올라가는 상대 경로 대신 `@/` 별칭을 쓴다.

## 무엇을 확인해야 하는가

이 프로젝트에는 테스트 프레임워크가 없다. `npm run lint`와 `npm run build`가 모두 종료 코드 0을
내야 작업이 끝난 것이다. 그 외에 손으로 확인할 것들:

- **모델 로딩**: 브라우저에서 `/human-body.glb` 요청이 성공하고, 머리부터 발끝까지 잘리지 않고
  보이는지. 창 크기를 바꿔도 마찬가지인지.
- **부위 선택**: 왼쪽 무릎을 눌렀을 때 `left_knee`가 나오고 **그 부위만** 색이 바뀌는지. 다른
  부위가 함께 물들면 재질 복제를 빠뜨린 것이다.
- **좌우**: 정면에서 화면 오른쪽에 보이는 무릎을 눌렀을 때 `left_knee`가 나오는지. 모델을 180도
  돌려 누른 뒤에도 같은 식별자가 나오는지.
- **앞뒤 판별**: 정면에서 가슴을 눌러 `front`, 180도 돌려 같은 부위를 눌러 `back`이 나오는지.
- **드래그와 누르기**: 모델을 크게 한 바퀴 돌리고 손을 뗐을 때 아무 부위도 선택되지 않는지.
  모바일 화면 크기로 줄여 놓고 확인한다.
- **작은 부위**: 손목과 발목을 확대해서 고를 수 있는지. 이름 목록으로도 고를 수 있는지.
- **저장소를 읽는 화면**: 새로고침했을 때 브라우저 콘솔에 하이드레이션 경고가 없어야 한다.
  저장소 읽기는 `useEffect` 안에서 하고, 렌더 본문에서 하지 않는다.
- **AI 실패**: 키를 비운 채 대화를 시도했을 때 화면이 실패를 알리고, 체크한 증상이 지워지지 않고,
  그 상태로 저장이 되는지.
- **기록 수정**: 고쳐 저장했을 때 새 기록이 생기지 않고 기존 기록이 바뀌는지, 그리고 목록의 맨
  위로 올라오는지.
- **빈 상태**: 기록이 하나도 없을 때 홈이 강조 없는 인체 모델로 정상적으로 보이는지. 증상 목록이
  비어 있는 부위에서 진단을 시작할 수 있는지.
