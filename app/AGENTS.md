# `app/`

이 앱의 모든 실행 코드가 여기 있다.

## 담당하는 것

| 경로 | 담당 |
|---|---|
| `layout.tsx` | 모든 화면을 감싸는 틀, 전역 폰트와 스타일 연결 |
| `page.tsx` | 홈 화면 — 인체 그림 위의 기록 마크, 마크를 눌러 펼치는 기록 목록 |
| `diagnose/page.tsx` | 진단 화면 — 부위 선택, 증상 체크, AI 대화, 저장 |
| `api/chat/route.ts` | OpenAI 호출 통로. 서버에서만 실행된다 |
| `components/` | 화면을 이루는 조각들 |
| `lib/` | 데이터와 계산 — 부위 목록, 기록 저장, 증상 계산, 통로 호출 |

## 담당하지 않는 것

- **인체 이미지와 정적 파일**은 `public/`에 둔다. 여기에 이미지 파일을 넣지 않는다.
- **빌드·검사 설정**은 프로젝트 루트의 `next.config.ts`, `eslint.config.mjs`, `tsconfig.json`,
  `postcss.config.mjs`가 갖는다. 여기서 설정을 바꾸지 않는다.
- **환경변수 파일**(`.env.local`)은 프로젝트 루트에 둔다.
- 서버에 데이터를 저장하는 코드는 여기 없다. 이 앱에는 서버 데이터베이스가 없다.

## 항상 지켜야 하는 것

- **`localStorage`를 부르는 곳은 `lib/records.ts` 한 곳이다.** 화면과 컴포넌트가 저장소를 직접
  읽거나 쓰지 않는다. `lib/records.ts` 밖에 `localStorage`라는 이름이 나오면 어긴 것이다.
- **OpenAI를 부르는 곳은 `api/` 아래의 Route Handler뿐이다.** 지금은 `api/chat/route.ts` 하나다.
  브라우저에서 실행되는 코드가 OpenAI 주소를 부르거나 API 키를 읽지 않는다. `api/` 밖에 OpenAI
  호출이 나오면 어긴 것이다.
- **API 키는 `api/chat/route.ts`에서 `process.env.OPENAI_API_KEY`로만 읽는다.** 환경변수 이름에
  `NEXT_PUBLIC_` 접두사를 붙이지 않는다. 붙이면 키가 브라우저 번들에 그대로 들어간다.
- **`components/BodyMap.tsx`는 기록을 다루지 않는다.** 인체 그림을 그리고 눌린 부위의 식별자를
  바깥으로 알릴 뿐이다. `lib/records.ts`나 `lib/symptoms.ts`를 가져오면 어긴 것이다. 이 경계가
  있어야 나중에 그림을 3D로 바꿀 때 이 파일만 갈아끼우면 된다.
- **부위 식별자 문자열은 `lib/bodyParts.ts`에서만 나온다.** 다른 파일에 `"front."`이나 `"back."`
  으로 시작하는 문자열을 직접 써넣지 않는다.
- **의존 방향은 화면 → `components/` → `lib/` 한 방향이다.** `lib/` 안의 파일이 컴포넌트나 화면을
  가져오지 않는다.
- **기본은 Server Component다.** `"use client"`는 상태·이벤트·브라우저 API가 필요한 컴포넌트에만
  붙이고, 트리의 되도록 아래쪽에 붙인다.

## 이 폴더의 작성 방식

- 화면에 보이는 문자열은 한국어, 코드 안의 이름은 영어다.
- 컴포넌트 파일은 `PascalCase.tsx`이고 파일 이름과 기본 내보내기 이름이 같다. `lib/` 아래
  파일은 `camelCase.ts`다.
- 스타일은 Tailwind CSS 유틸리티 클래스로 쓴다. 새 `.css` 파일을 만들지 않는다. 전역 스타일이
  필요하면 `globals.css`에 넣는다.
- `any`를 쓰지 않는다. 타입 단언을 쓸 때는 바로 윗줄에 왜 안전한지 주석을 남긴다.
- 다른 폴더로 올라가는 상대 경로 대신 `@/` 별칭을 쓴다.

## 무엇을 확인해야 하는가

이 프로젝트에는 테스트 프레임워크가 없다. `npm run lint`와 `npm run build`가 모두 종료 코드 0을
내야 작업이 끝난 것이다. 그 외에 손으로 확인할 것들:

- **저장소를 읽는 화면**: 새로고침했을 때 브라우저 콘솔에 하이드레이션 경고가 없어야 한다.
  저장소 읽기는 `"use client"` 컴포넌트의 `useEffect` 안에서 하고, 렌더 본문에서 하지 않는다.
- **부위 선택**: 왼쪽과 오른쪽이 서로 다른 부위로 저장되는지. 한쪽에 남긴 기록이 반대쪽 마크에
  나타나면 안 된다.
- **앞뒤 전환**: 뒷면 부위에 남긴 기록의 마크가 뒷면으로 전환했을 때 보이는지.
- **AI 실패**: 키를 비운 채 대화를 시도했을 때 화면이 실패를 알리고, 체크한 증상이 지워지지 않고,
  그 상태로 저장이 되는지.
- **기록 수정**: 고쳐 저장했을 때 새 기록이 생기지 않고 기존 기록이 바뀌는지, 그리고 목록의 맨
  위로 올라오는지.
- **빈 상태**: 기록이 하나도 없을 때 홈이 마크 없는 인체 그림으로 정상적으로 보이는지. 증상
  목록이 비어 있는 부위에서 진단을 시작할 수 있는지.
